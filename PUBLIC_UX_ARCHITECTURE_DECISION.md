# Public UX architecture decision

Status: accepted for implementation

Date: 2026-09-18

## Decision

Keep the public UX inside `lokesh0186/ardguard` under `site/` and deploy it as a
static GitHub Pages artifact.

The site uses semantic HTML, CSS, and a small amount of dependency-free browser
JavaScript. It visualizes immutable scenario fixtures generated by the public
`ardguard==0.1.0b4` wheel. It does not evaluate eligibility in JavaScript.

## Why this option

- The experience is static and requires no server, account, credentials, or
  network provider.
- A separate frontend repository would split documentation, fixtures, issue
  tracking, and release provenance without providing a security benefit.
- A React/Next dependency tree is unnecessary for scenario selection, tabs,
  copy buttons, local search, and JSON disclosure.
- GitHub Pages can host the complete experience with read-only deployment
  permissions separated from the PyPI Trusted Publishing workflow.
- The landing-page explanation remains readable without JavaScript. The Explorer
  requires JavaScript only to load and render precomputed local fixtures; a load
  failure is explicit and never attempts evaluation.

## Decision authority

`ardguard==0.1.0b4` is the sole decision authority.

The generation path is:

```text
scenario input JSON
        |
        v
public Beta-4 Python package
        |
        v
Decision + DecisionReceipt fixture
        |
        v
static Explorer display
```

The browser may select and render fixtures. It may not calculate requirement
verdicts, eligibility, fallback, reason codes, hashes, or selections.

## Security and privacy

- No live evaluator in this phase.
- No plugin loading, network providers, URL fetching, file access, environment
  interpolation, credentials, telemetry, analytics, login, or persistence.
- Fixture strings are rendered with `textContent`, never injected as HTML.
- A static Content Security Policy restricts executable content and fixture fetches to
  the site origin and disallows objects, form submission, and external connections.
- GitHub Pages does not provide a repository-defined HTTP response-header policy, so a
  reliable `frame-ancestors` directive is not claimed. This is a read-only residual risk,
  not a decision-engine exposure.
- The deployment workflow has Pages-only permissions and is independent of the
  package release workflow.

## Versioning

This is documentation, fixture, example, and static-site work. The Python
package version remains `0.1.0b4`; no Beta 5 is created.

## Deferred option

A live evaluation service is explicitly deferred. It would require an
intentionally hardened wrapper, resource limits, rate limiting, strict schemas,
and a separate hosting decision. The static Explorer satisfies the no-install
goal without introducing that attack surface.
